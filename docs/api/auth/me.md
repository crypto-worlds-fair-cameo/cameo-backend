# GET /api/auth/me — 현재 사용자 조회

- 상태: 설계 확정, 구현 예정. 현재 제공 중인 API가 아니다.
- 설계 기준일: 2026-10-01
- 경로는 `API_PREFIX=api` 기준이며 경로 접두사를 비우면 `/auth/me`다.

## 목적과 인증

현재 세션의 서비스 사용자와 세션 만료 시각을 조회한다. 프론트가 새로고침 후 로그인 상태를 복원할 때 사용한다. 지갑의 연결 상태만으로 서비스 로그인 상태를 추정하지 않는다.

운영은 `__Host-cameo_session`, 로컬 HTTP는 `cameo_session` 쿠키가 필요하다. Bearer 토큰이나 지갑 주소 쿼리로 인증하지 않는다.

## 요청

| 항목 | 계약 |
| --- | --- |
| 경로 매개변수 | 없음. |
| 본문 / 쿼리 | 사용하지 않음. 전달되어도 무시. |
| 쿠키 | 세션 쿠키 필수. |
| `Origin` | 다른 출처로 보내는 프론트 요청에 브라우저가 자동으로 포함. 허용된 요청 출처에서 CORS 응답을 받을 수 있음. POST 전용 요청 출처 필수 검증은 이 GET에 적용하지 않음. |

```http
GET /api/auth/me
Origin: https://app.example.com
Cookie: __Host-cameo_session=<opaque-session-token>
```

프론트는 `credentials: 'include'`를 사용한다. 새 SIWS 서명은 필요하지 않다.

쿼리는 정의된 항목이 없으므로 모두 무시한다. 본문에도 허용 필드가 없으며, 본문 유무·추가 필드·값으로 조회 대상이나 연장 여부를 바꾸지 않는다. 본문·`Content-Type` 누락 또는 사용하지 않는 매체 타입 자체를 이유로 400을 반환하지 않는다. 전역 HTTP 파서가 선택한 본문은 파싱·크기 제한을 따른다. 문법·디코딩 오류는 400, 파서의 크기 제한 초과는 413, 지원하지 않는 charset·Content-Encoding은 415다. 파싱하지 않는 매체 타입은 업무 입력으로 사용하지 않는다.

## 요청 쿠키 처리

세션 토큰은 난수 32바이트를 표현한 패딩 없는 Base64url 43자다. 길이·문자 집합·디코딩 결과 32바이트·재인코딩 일치를 확인한다. 값을 URL 디코딩하거나 잘못된 형식을 보정하지 않는다. 같은 이름의 쿠키가 두 개 이상이면 값이 같아도 무효이며 첫 번째나 마지막 값을 임의로 선택하지 않는다.

정규 토큰은 SHA-256 소문자 16진수 64자 해시로 변환해 `auth_sessions.token_hash`를 조회한다. 누락·빈 값·형식 오류·동일 이름 중복은 DB 조회 없이 `401 AUTH_SESSION_INVALID`이며 세션 쿠키를 삭제한다. 브라우저 연결 쿠키는 인증에 사용하거나 변경하지 않는다.

## 성공 응답

HTTP 200, `Cache-Control: no-store`. [로그인 응답](login.md)의 `data.user`와 `data.session`과 같은 구조다.

```json
{
  "statusCode": 200,
  "success": true,
  "data": {
    "user": {
      "id": "95416ea1-fcf7-4e88-a58d-3e2e88543bc8",
      "displayName": "사용자-a7f29c41",
      "avatarUrl": null,
      "wallets": [
        {
          "chainNamespace": "solana",
          "address": "6xtn9dTbszpUkeqsgaU4oQwSXBPFkGUHdQTaG2Zeoc8L"
        }
      ]
    },
    "session": {
      "expiresAt": "2026-10-09T03:00:10.000Z",
      "absoluteExpiresAt": "2026-10-31T03:00:10.000Z"
    }
  }
}
```

예시는 10월 1일 생성한 세션을 10월 2일 조회하여 미접속 만료가 연장된 경우다.

`user.id`는 UUID, `displayName`과 `avatarUrl`은 문자열 또는 null이며 필드를 생략하지 않는다. `wallets`는 연결된 지갑 배열이고 원래 주소와 체인을 반환한다. 배열은 생성 시각, 동일 시각이면 지갑 UUID 순으로 정렬한다. 빈 배열도 표현할 수 있다. 두 만료 필드는 UTC ISO 8601 문자열이다. 세션 ID와 토큰·해시를 반환하지 않는다.

## 세션 연장과 쿠키

인증에 성공한 조회를 활동으로 계산한다. 유스케이스가 최종 인증 확인·사용자 상태 확인·세션 연장·응답 정보 조회를 같은 트랜잭션에서 처리한다.

1. 토큰 해시로 세션과 `user_id`를 예비 조회한다. 행이 없으면 미로그인 결과이며, 이 조회만으로 인증 성공을 확정하지 않는다.
2. `users` 행을 먼저 잠그고 해당 `auth_sessions` 행을 잠근 뒤 다시 읽는다. 잠금 순서는 기존 로그인의 사용자 잠금 후 세션 폐기 순서와 맞춘다. 다시 읽은 행이 제출 토큰·사용자에 대응하는지 확인하며, 예비 조회나 가드에서 읽은 상태를 최종 판단에 재사용하지 않는다.
3. 필요한 행 잠금을 모두 얻은 뒤 `date_trunc('milliseconds', clock_timestamp())`를 한 번 평가한 시각 `t`로 만료를 판정한다. 트랜잭션 시작 시각인 `now()`·`CURRENT_TIMESTAMP`나 앱의 `Date.now()`를 사용하지 않는다. 잠금 대기 중 만료된 세션도 거절한다.
4. 세션 없음·`revoked_at IS NOT NULL`·`expires_at <= t`·`absolute_expires_at <= t`이면 미로그인 결과다. 유효한 세션이지만 잠금 뒤 읽은 사용자 `status`가 `active`가 아니면 비활성 계정 결과다. 두 조건이 함께 해당하면 세션 유효성 실패인 401을 우선한다. 두 실패 결과 모두 DB 행을 변경하지 않는다.
5. 활성 계정의 유효 세션만 `last_seen_at=t`, `expires_at=min(t+7일, absolute_expires_at)`로 갱신한다. 동일한 `t`를 판정과 갱신에 사용하며 `revoked_at IS NULL` 조건을 유지한다. 절대 만료·토큰 해시·생성 시각·폐기 시각은 바꾸지 않는다. 사용자·지갑 정보와 갱신한 만료를 조회한 뒤 커밋한다.

사용자 정지·탈퇴가 먼저 커밋됐다면 잠금 뒤 그 상태로 거절한다. `/me`가 먼저 잠금과 검증을 마쳤다면 해당 조회는 성공할 수 있으며 이후 사용자 상태 변경은 후속 요청에 적용된다. 이미 만료된 세션은 새 서명 없이 복구하지 않는다. 이 조회는 사용자 프로필·지갑·`last_login_at`을 변경하지 않는다.

커밋 성공을 확인한 뒤 같은 토큰을 남은 미접속 만료 기간으로 재발급한다. 운영 쿠키는 HttpOnly, Secure, SameSite=Lax, Path=/, Domain 생략이다. 로컬 HTTP는 환경에 맞는 쿠키 이름과 Secure=false를 사용한다.

쿠키 수명은 로그인과 같은 방식으로 DB 잔여 수명을 앱의 단조 시계 기준 만료 시각으로 변환하고, 이후 쿼리·커밋·응답 준비 경과를 차감한다. `Max-Age`는 남은 밀리초를 초로 나눠 올림하고 0보다 작으면 0으로 설정한다. 앱과 DB의 벽시계 차이로 수명을 계산하지 않는다. 실제 인증은 DB 만료로 판단하며 현재 시각이 두 만료 중 하나와 같아도 이미 만료된 세션이다.

## 구현 책임과 HTTP 경계

`me/`에 컨트롤러와 유스케이스를 두고, 기존 `wallet-account/`와 `session/`의 저장소를 같은 불투명 `TransactionContext`로 사용한다. 저장소가 별도 트랜잭션을 열거나 내부에서 커밋하지 않는다.

이 API에는 미로그인·비활성을 먼저 예외로 거절하는 인증 가드를 적용하지 않는다. 최종 검증과 연장은 유스케이스가 담당하고 성공·미로그인·비활성 결과를 반환한다. 컨트롤러는 확정된 결과로 성공 쿠키를 설정하거나 실패 쿠키를 삭제한 뒤 공개 업무 오류로 전환한다. DB 검증이 필요한 결과는 트랜잭션 종료가 확인된 뒤 처리한다. 공통 오류 필터에 인증 쿠키 정책을 넣지 않는다.

환경별 쿠키 이름·속성과 중복 쿠키 읽기는 `auth-http`, 정규 토큰 확인·해시는 `auth-secret`의 기존 정책을 사용한다. 이 GET에는 POST의 `auth-origin` 필수 출처 검증을 적용하지 않는다. 성공·실패 응답 모두 `Cache-Control: no-store`이며 토큰 원문·해시를 JSON과 로그에 포함하지 않는다.

본문 파서가 발생시킨 입력 오류는 HTTP 계층에서 아래 400·413·415 공개 예외로 변환한다. 현재 공통 필터는 HTTP 예외로 변환되지 않은 일반 오류를 500으로 처리하므로, 구현 시 프레임워크의 기본 변환만으로 이 계약을 충족한다고 가정하지 않는다. 이 변환에는 DB 접근이나 인증 쿠키 변경을 포함하지 않는다.

## 오류 응답

| 상태 / 코드 | 조건 | 공개 메시지 | 쿠키 |
| --- | --- | --- | --- |
| 400 `BadRequestException` | HTTP 요청 파싱 실패(잘못된 JSON 문법 등) | 요청 파싱 오류 메시지 | 변경하지 않음 |
| 413 `PayloadTooLargeException` | HTTP 파서의 본문 크기 제한 초과 | `요청 본문이 너무 큽니다.` | 변경하지 않음 |
| 415 `UnsupportedMediaTypeException` | 파서가 선택한 본문의 지원하지 않는 charset·Content-Encoding | `지원하지 않는 본문 인코딩입니다.` | 변경하지 않음 |
| 401 `AUTH_SESSION_INVALID` | 세션 쿠키 없음·잘못된 형식·동일 이름 중복·세션 없음·폐기·미접속/절대 만료 | `로그인이 필요합니다.` | 세션 쿠키 삭제 |
| 403 `AUTH_USER_UNAVAILABLE` | 세션은 확인되지만 계정이 활성 상태가 아님 | `이 계정으로 로그인할 수 없습니다.` | 세션 쿠키 삭제 |
| 429 `ThrottlerException` | IP 한도 초과 | `ThrottlerException: Too Many Requests` | 변경하지 않음 |
| 500 `INTERNAL_SERVER_ERROR` | DB·커밋 확인·응답 처리 등 내부 실패 | `Internal server error` | 아래 실패 단계에 따름 |

```json
{
  "statusCode": 401,
  "success": false,
  "code": "AUTH_SESSION_INVALID",
  "message": "로그인이 필요합니다.",
  "error": "Unauthorized",
  "traceId": "c9f2ea59-4f07-4b6d-a1b0-eb546ee18265"
}
```

삭제는 동일한 환경의 쿠키 이름과 적용 범위를 사용해 `Max-Age=0`으로 발급한다. 비활성 계정에서 이번 조회는 세션을 연장하지 않으며 서버의 기존 세션 행은 그대로 두고 사용자 상태로 접근을 거절한다. 내부 실패를 미로그인 401로 바꾸지 않는다.

## 실패 단계와 재시도

다음 표는 이번 조회의 변경만 설명한다. 다른 동시 요청의 변경을 되돌리지 않는다. 쿠키 변경은 서버가 발급하는 `Set-Cookie`이며 브라우저 수신까지 보장하지 않는다.

| 결과 | 세션 DB 상태 | 세션 쿠키 |
| --- | --- | --- |
| 200 성공 | 활동·미접속 만료 갱신 커밋 | 같은 토큰 재발급 |
| 401 미로그인 / 403 비활성 | 변경 없음 | 삭제 |
| 400·413·415 요청 파싱 오류 / 429 요청 제한 | 변경 없음 | 변경 헤더 발급 안 함 |
| 500 내부·DB 오류, 롤백 확인 | 이번 조회의 갱신 롤백 | 변경 헤더 발급 안 함 |
| 500 COMMIT 결과 확인 실패 | 갱신 커밋 여부 불명 | 변경 헤더 발급 안 함 |
| 500 업무 결과 확정 후 응답 처리 오류 | 확정된 갱신 또는 미변경 결과 유지 | 전달 여부 불명 |

확인된 커밋은 쿠키 구성·응답 직렬화·전송 실패 때문에 되돌리지 않는다. DB 조회 없는 미로그인 결과도 쿠키 처리 중 실패하면 공개 500이 될 수 있으며 DB는 변경하지 않는다. 응답 전송 전 오류는 공개 500으로 처리하고 이미 전송을 시작했다면 연결이 종료될 수 있다. 쿠키는 미전달·일부 전달·전달 여부 불명일 수 있다. 실패 단계나 DB 내부 상태를 JSON에 노출하지 않는다.

500·네트워크 오류만으로 로그아웃 상태를 확정하거나 쿠키가 유지됐다고 단정하지 않는다. 다른 인증 요청과 겹치지 않게 조회를 다시 수행하여 200·401·403으로 현재 상태를 확인한다. 429는 `Retry-After` 이후 재시도한다. 반복 조회는 성공할 때마다 활동으로 계산하므로 응답의 미접속 만료가 같다는 멱등 계약은 아니다.

## 인증 요청 경합과 프론트 처리

DB에서 폐기된 세션은 연장으로 되살리지 않는다. `/me` 갱신이 먼저 커밋된 뒤 로그아웃이 폐기하면 후속 인증은 실패하고, 로그아웃이 먼저 폐기하면 `/me`는 401이다. 이는 브라우저가 마지막에 적용할 쿠키까지 보장하는 규칙은 아니다.

이전 세션 S0의 `/me`가 성공한 뒤 새 로그인으로 S1이 발급되고, 늦은 `/me` 응답이 S0을 설정하면 S1 쿠키가 덮일 수 있다. 늦은 `/me` 401·403의 쿠키 삭제도 새 로그인 쿠키를 삭제할 수 있다. S0이 폐기됐다면 S0 자체는 인증되지 않지만 S1을 브라우저가 유지한다고 보장할 수 없다.

프론트는 같은 탭에서 챌린지 발급·서명·로그인, `/me`, 로그아웃을 동시에 실행하지 않는다. 로그인·로그아웃 중 자동 조회를 멈추고, 이미 보낸 인증 요청의 응답 처리를 마친 뒤 다음 흐름을 시작한다. 오래된 응답 JSON을 무시하는 것만으로는 브라우저의 `Set-Cookie` 적용을 막지 못한다. 요청 취소나 네트워크 오류도 서버 트랜잭션 취소를 보장하지 않는다.

여러 탭은 API 호스트의 쿠키를 공유하며 같은 탭의 직렬화만으로 탭 사이 경합을 제거할 수 없다. 서버는 브라우저 전체의 단일 활성 세션이나 로그아웃 이후의 새 로그인 차단을 보장하지 않는다. 경합 후에는 겹치는 요청이 끝난 뒤 `/me`로 현재 상태를 확인한다. 로그인 성공 복구는 [로그인 스펙](login.md)의 선택 지갑 일치 확인을 함께 적용하고, 로그아웃 경합은 [로그아웃 스펙](logout.md)을 따른다.

## 완료 검증

아래 항목은 구현 시 확인할 기준이며 현재 API를 실행해 확인한 결과가 아니다.

- 로그인 쿠키로 사용자 정보가 복원되고 기존 이름·아바타가 유지되는지 확인한다.
- 본문·쿼리가 전달되어도 무시하고 현재 세션의 사용자를 조회하는지 확인한다.
- 본문 파서의 문법·디코딩 오류 400, 크기 제한 초과 413, 지원하지 않는 인코딩 415에서 DB·쿠키를 변경하지 않는지 확인한다.
- 활동 시각과 미접속 만료가 갱신되지만 절대 만료를 넘지 않는지 확인한다.
- 두 만료 시각과 정확히 같은 시각, 폐기된 세션, 잘못된 토큰은 401이며 쿠키가 삭제되는지 확인한다.
- 비활성 계정은 403이며 세션을 연장하지 않는지 확인한다.
- 로그아웃과 동시에 요청해도 폐기된 세션이 다시 유효해지지 않는지 확인한다.
- 동일 값 중복 쿠키·비정규 Base64url은 DB 조회 없이 401이고 연결 쿠키는 유지되는지 확인한다.
- 로그인과 같은 사용자 후 세션 잠금 순서를 사용하고, 대기 중 만료·사용자 정지·탈퇴를 잠금 뒤 재확인하는지 확인한다.
- 판정 시각을 한 번만 평가해 만료 직전·절대 만료 경계에서 DB 시각 제약 오류 없이 처리하는지 확인한다.
- 앱·DB의 시계 차이와 커밋 대기 시간이 쿠키 수명을 늘리지 않는지 확인한다.
- 롤백 확인·COMMIT 결과 불명·확정 후 응답 실패를 구분하고 내부 실패를 401로 가장하지 않는지 확인한다.
- 늦은 재발급·삭제가 새 로그인 쿠키에 영향을 줄 수 있음을 프론트가 처리하고 인증 요청을 겹치지 않게 실행하는지 확인한다.
- 사용자 정보를 캐시하지 않고 토큰·해시·세션 ID를 노출하지 않는지 확인한다.
